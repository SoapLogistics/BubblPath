# Solomon AI Orchestrator: The 18-Phase Capability Blueprint

This document represents the finalized architectural master plan for the **Solomon Perpetual Learning Machine**. Through aggressive iterative deployments, the core `/chat` gateway has been transformed from a standard text generator into a secure, self-healing, locally executing swarm orchestrator.

By strategically parsing exact linguistic output tokens generated by the core LLM, Solomon dynamically delegates tasks, optimizes quantization heuristics, executes code in Python sandboxes, and rewrites its own memory structures on-the-fly.

---

## Part 1: Contextual Awareness & Persona Grounding

*   **Phase 1: Semantic Retrieval-Augmented Generation (RAG)**
    *   **Hook:** Automatic on `/chat`.
    *   **Action:** Compares incoming prompts against the `Mnemosyne` SQLite database using local L2-normalized vector similarity. It pulls top conversational memory cards directly into the system prompt.
*   **Phase 2: Persona and Communication Infusion**
    *   **Hook:** Automatic on `/chat`.
    *   **Action:** Hardcodes the system behavior to maintain a highly nuanced, fluid conversational state parallel to flagship models like Gemini or GPT-4, shifting it away from acting like a rigid database unless explicitly commanded.
*   **Phase 11: Active Context Budgeting**
    *   **Hook:** Automatic on `/chat` retrieval.
    *   **Action:** Imposes a strict 2,000-character ceiling on historical memory injection. Drops the lowest-confidence memory cards and pushes a `[CONTEXT TRUNCATED]` warning to the LLM to prevent sequence length maximums and contextual hallucination.

---

## Part 2: Model Routing & Output Telemetry

*   **Phase 3: Adaptive Conversational Routing**
    *   **Hook:** Automatic on `/chat`.
    *   **Action:** Evaluates prompt complexity against active SOK cards. Routes simple queries to an ultra-light quantized framework (INT4/Ternary), and demanding logic queries to a high-precision framework (FP16), minimizing active VRAM footprints.
*   **Phase 4: Structured Output Telemetry**
    *   **Hook:** Automatic on `/chat` response generation.
    *   **Action:** Appends a strict `[TELEMETRY]` JSON-like block to the bottom of all conversational responses detailing the Model Routed, Latency in milliseconds, and the retrieval Confidence metrics.

---

## Part 3: Dynamic Code Generation & Execution

*   **Phase 5: Generative Code Synthesizer (AST Hook)**
    *   **Hook:** `[SYNTHESIZE_AST_HOOK: <method_name>]` + ````python ... ````
    *   **Action:** Leverages `ASTInjector` to dynamically rewrite and hot-reload target Python classes on the server by parsing new methods directly from the AI's chat text.
*   **Phase 6: Subprocess Execution Hook**
    *   **Hook:** `[EXECUTE_SKILL: <skill_name>]`
    *   **Action:** Pipes generated Python scripts into `SandboxExecutor`, running them within a constrained timeout isolation block and dynamically streaming `stdout` back into the chat as `[SANDBOX EXECUTION]`.
*   **Phase 9: Observational Simulator Hook**
    *   **Hook:** `[OBSERVE_BINARY: <binary_name>]`
    *   **Action:** Prompts Solomon to profile closed-source binary execution behavior on the host machine and immediately synthesize clean-room Python replacements to emulate that binary.

---

## Part 4: Cognitive Diagnostics & Learning Loops

*   **Phase 7: Recursive Telemetry Crucible Hook**
    *   **Hook:** `[ANALYZE_TELEMETRY]`
    *   **Action:** Directs the `RecursiveCrucible` to process latency and VRAM telemetry logs, autonomously triggering structural application refactoring (AST-FUSION/AST-PRUNE) to self-heal performance degradation.
*   **Phase 8: Perpetual Learning Loop Hook**
    *   **Hook:** `[INITIATE_LEARNING_CYCLE]`
    *   **Action:** Forces Solomon to iterate through the complete 7-stage learning cycle (Observe -> Understand -> Build -> Test -> Remember -> Teach Itself -> Repeat), validating draft skills and promoting them to active memory.
*   **Phase 15: Reflection and Confidence Reinforcement Hook**
    *   **Hook:** `[REINFORCE: <card_id>|<outcome>]`
    *   **Action:** Adjusts the mathematical retrieval weight of past semantic knowledge cards based on whether historical guidance succeeded or failed during current sandbox execution steps.

---

## Part 5: Swarm Management & Logic Pathing

*   **Phase 10: Skill Graph Orchestration Hook**
    *   **Hook:** `[ORCHESTRATE_SKILLS: <root_skill>]`
    *   **Action:** Leverages a Directed Acyclic Graph (DAG) to map out topological sequence requirements, displaying the step-by-step pipeline necessary to execute a complex objective.
*   **Phase 12: Operator Configuration Hook (Fallback Logic)**
    *   **Hook:** `[UPDATE_WORKER_MODE: <worker_name>:<mode>]`
    *   **Action:** Dynamically elevates or limits security execution clearance levels (e.g., READ_ONLY, LIVE) for internal sub-agents like Gabriel or Loki.
*   **Phase 13: Active Memory Consolidation Hook**
    *   **Hook:** `[MEMORIZE: <family>|<focus>|<content>]`
    *   **Action:** Implements Generation-Augmented Retrieval by allowing Solomon to permanently record its own discoveries or rules securely into the SQLite relational schema mid-conversation.
*   **Phase 14: Sub-Agent Delegation Hook**
    *   **Hook:** `[DELEGATE: <worker_name>|<task_description>]`
    *   **Action:** Intercepts tasks and farms them out to specialized worker engines based on their active capability modes, solidifying Solomon as the Master Foreman.
*   **Phase 16: Zero-Shot Skill Graph Node Injection**
    *   **Hook:** `[INJECT_SKILL_NODE: <skill_name>|<dependency1,dependency2>]`
    *   **Action:** Dynamically writes brand new node structures into the `SkillGraph`, repairing broken or missing workflow topologies on the fly.

## Part 6: Local Quantization Optimization

*   **Phase 17: Local Quantization Optimizer (The Compiler)**
    *   **Hook:** Background integration.
    *   **Action:** Translates ILP multi-choice knapsack math into executable script strings. Compiles SOK dataset calibration memory securely into actionable `llama.cpp` and `Ollama` syntax models.
*   **Phase 18: Self-Healing Offline Inference Bridging**
    *   **Hook:** `[COMPILE_SOLOMON_LLM: <target_ram_mb>]`
    *   **Action:** Calculates the optimal mixed-precision state for an active target RAM footprint constraint and prints out the exact terminal commands Solomon needs to run to spin up its own highly optimized, fully offline AI clone.

---

## Critical Security Posture
All autonomous hooks capable of executing live logic (AST injections, subprocess sandboxes, and learning loops) are strictly safeguarded by loopback binding (`127.0.0.1`). Any attempts to invoke the REST capability execution API endpoints from an external interface are permanently blocked with a 403 HTTP status, mitigating all risks associated with Remote Code Execution (RCE).
